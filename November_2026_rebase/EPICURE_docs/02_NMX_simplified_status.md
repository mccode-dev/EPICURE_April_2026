## 3. Findings

How these were checked: by reading the code, plus a host-only compile with Apple clang 21,
`-O2 -Wall`. That compile succeeds with two warnings: `j` uninitialized (12970) and the generic
`par6`. Later, host-fallback runs were added (see §5). No GPU was available, so nothing below
has been confirmed on a device.

### Correctness bugs (must fix before anything is upstreamed)

1. **`hkl_search`: `j` is used uninitialized.** `int i, j;` … `j++`. clang confirms it. The
   returned `tau_count` is garbage (undefined behaviour). On the GPU it only feeds the dead
   `if (j >= tau_count)` check. On the CPU it pollutes `hkl_info.max_tau_count` and `nb_refl`.
   Fix: `j = 0`.
2. **The CPU `SPLIT` reuse path selects no reflection.** When `ki` matches the cached `ki`
   (order 1, the `SPLIT` repeats), `hkl_search` is skipped, but the reflection index `i` is
   now chosen *inside* `hkl_search`. `L[i]` then uses a stale `i`. The GPU path is not
   affected because the cache is compiled out there. CPU results with `SPLITS>1` are wrong.
3. **Reservoir edge case.** On the first candidate `rand0max(total) < refl` is
   `refl*rand01() < refl`. That is false when `rand01()` returns exactly 1.0, so `sel` stays
   −1 and `i` falls back to 0 (reflection `L[0]`). It is rare, but AGENTS.md calls out
   exactly this. Fix: `if (sel < 0 || rand0max(total) < refl)`.
4. **The monitors' flat index is transposed against the host layout.** `create_darr2d(nx,ny)`
   is row-major (`a[i] = &p[i*ny]`), so `a[i][j]` ≡ `a[0][i*ny + j]`. 04 uses
   `i + ny*j` (PSD), `i + nv*j` (Divergence), `j + nt*i` (TOFLambda) and `i + nh*j`
   (DivLambda). Every NMX monitor is square (90², 100², 500², 100²), so nothing goes out of
   bounds, but **all 2D outputs come out transposed** compared with the CPU. PW already fixed
   the same bug on `02` (`cd33945`) and it was never carried over to 04. A non-square monitor
   would write out of bounds.
5. **Monitor_nD n1D (`Flag_Multiple`) is broken by the rewrite.** The allocation uses a stale
   `i` (`Coord_Number*Coord_Bin[i]`) and a `Coord_Bin[1]×Coord_Bin[2]` shape. The index is
   turned into a mixed-radix product, so separate 1D histograms become one N-D index. NMX
   does not use this mode, so the instrument is fine, but this must not go upstream as is.
6. **Monitor_nD list mode has a race.** Each coordinate gets an `atomic write` at
   `Buffer_Counter`, followed by a separate `Buffer_Counter++`. Two threads can therefore
   claim the same row. **`main` has already fixed this** with `atomic capture` of the slot, and
   the fresh start inherits the fix.

### Limitations

7. **FUNNEL is not ported in 04.** `raytrace_all_funnel` still has shallow
   `map(tofrom: _X_var)`, which leaves `hkl_list` and the monitor arrays unmapped. The working
   FUNNEL version is on `02_work_joachim` (`b8ebef4`).
8. The FUNNEL kernels map `particles[0:n]` `tofrom` **for each kernel**, which means a full
   host↔device round trip per component group. That needs an enclosing
   `target data map(alloc:)` and updates only at CPU-only segments.
9. The switch is `_OPENMP`, which host-only `-fopenmp` builds also define.
10. `struct tau_data {}` is now empty. That is a GNU extension: invalid ISO C, and rejected by
    MSVC. It is harmless for nvc, CCE, gcc and clang.
11. The deep maps are hand-written per instance. There are 87 components, but only 10 need deep
    maps. The code generator cannot write these maps itself because it does not know array
    sizes (see the design doc §3).

### Numerical behaviour (AGENTS.md rule 5)

- **Reservoir selection draws one extra random number for each reachable reflection.**
  Results are statistically equivalent to stock Single_crystal (the same selection
  probability `refl_i / Σrefl`) but **not bit-comparable** under a fixed seed. Compare by
  χ² on monitors, not with `diff`.
- The monitor transposition (finding 4) is a *real* output difference, not noise.
- Neither of these is documented in the branch.

## 4. Verdict

04 is a **good, nearly complete specification** of what an OpenMP NMX build needs. The
offload structure is right, the declare-target and deep-map set is right, and the
Single_crystal stack problem has an algorithmic solution. It is **not** a validated result:
findings 1–4 change output, there are no committed timings or CPU comparisons, and FUNNEL is
missing.

### Fixed version

Findings 1–4 are fixed in `lumi_test/A_04_fixed/NMX_simplified.c`, each marked `FIX(n)` in the
source. Finding 2 is fixed by disabling the CPU reuse cache. The upstream component still needs
a proper decision on that (design doc, open decision 3).

## 5. Host-fallback results (macOS, clang 21 + libomp)

1e8 rays, seed 1234, slits and pinhole opened to 1 cm, `SPLITS=20`, compared with stock `main`
on the CPU.

| Run | Before the crystal | After the crystal | Flagged |
|---|---|---|---|
| Fixed 04 (variant A) | \|z\| ≤ 1.04, χ²/dof 0.86–1.00 | \|z\| ≤ 0.71, χ²/dof 0.95 | 0 |
| Unfixed 04 (control) | same, except `At_SampleOverviewDIVVDIVH.pos`: χ²/dof 2.08, 0.91 against its transpose | \|z\| ≤ 0.92 | 1 (transposed) |

**What this shows:** the fixed physics agrees with stock `main`, and the transposition was real.
**What it does not show:** anything about device memory, the deep maps, atomics under real
concurrency, or speed. The host fallback runs as a single team, in about the serial CPU time.

The next step is variants B2 and A on LUMI (`lumi_test/README.md`). B2 moves the same heap data
as 04, built from current `main`. 04 stays the reference for which data must move.

A point checked during B2: Elliptic_guide_gravity's `segLength` and `mValues*` are heap pointers
not mapped in 04, but TRACE only uses them when `enableSegments` is set, and that needs `mvalues*`
parameters, which NMX does not pass. So 04 is fine here. 04's kernel form (`target teams` + `loop`)
may give one thread per team on clang-based compilers (see the design doc §1.2); not verified.
